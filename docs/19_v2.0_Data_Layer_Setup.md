# Ellines EIP 2.0 — Data Layer Setup Guide

## Overview

The v2.0 data layer provides the foundation for advanced AI capabilities, autonomous self-healing, and real-time analytics. This document covers the setup and architecture of all data storage systems.

## Data Storage Systems

### 1. PostgreSQL (Supabase)

**Purpose**: Primary relational database for operational data

**Stores**:
- Organizations, users, authentication
- Connector installations and configurations
- Approval workflows and business rules
- Dashboards and widgets
- AI model registry metadata
- Remediation playbook entries
- Knowledge graph entity metadata (sync tracking)
- Federated learning rounds

**Technology**: PostgreSQL 16 via Supabase (EU West 2)

**Access**:
- Development: Local PostgreSQL or Supabase
- Production: Supabase pooler connection

**Schema Management**: Prisma ORM

**Documentation**: See existing schema in `services/identity/prisma/schema.prisma`

### 2. Neo4j Knowledge Graph

**Purpose**: Graph database for enterprise knowledge representation

**Stores**:
- **Entities**: Person, Product, Location, Event, Document
- **Relationships**: Works_At, Purchased_By, Attended, etc.
- **Properties**: Confidence scores, evidence, timestamps
- **Patterns**: Multi-hop relationships, causal chains

**Technology**: Neo4j 5.15 Community Edition

**Access**:
- Bolt: `bolt://localhost:7687`
- Browser: `http://localhost:7474`
- Credentials: `neo4j / eip_neo4j_password`

**Schema**: Defined in `infra/neo4j/init-schema.cypher`

**Documentation**: `infra/neo4j/README.md`

**Validates Requirements**: 2.1, 17.1, 17.2, 17.3

### 3. InfluxDB Time-Series Metrics

**Purpose**: High-performance time-series database for metrics

**Stores**:
- **Performance Metrics**: API latency, throughput, resource usage
- **Health Metrics**: Service availability, error rates, uptime
- **Business Metrics**: Active users, data sync operations
- **Security Metrics**: Auth attempts, rate limit violations

**Technology**: InfluxDB 2.7

**Access**:
- HTTP API: `http://localhost:8086`
- UI: `http://localhost:8086`
- Credentials: `eip_admin / eip_influx_password`
- Token: `eip_influxdb_admin_token_dev_only`

**Default Bucket**: `platform_metrics` (90 day retention)

**Documentation**: `infra/influxdb/README.md`

**Validates Requirements**: 4.1, 4.6, 11.1, 17.3, 21.6

### 4. Redis Distributed Cache

**Purpose**: In-memory cache and session store

**Stores**:
- **Cached Data**: API responses, query results, aggregations
- **Sessions**: User sessions, temporary workflow state
- **Rate Limiting**: Request counters, sliding windows
- **Locks**: Distributed locks for sync operations
- **Pub/Sub**: Real-time dashboard updates, event notifications

**Technology**: Redis 7

**Access**:
- URL: `redis://127.0.0.1:6379`
- CLI: `docker exec eip-redis redis-cli`

**Configuration**: 256MB max memory, LRU eviction, AOF persistence

**Documentation**: `infra/redis/README.md`

**Validates Requirements**: 21.1, 21.2

## Quick Start

### 1. Start All Data Services

```bash
# From project root
npm run docker:up

# This starts:
# - PostgreSQL (port 5432)
# - Redis (port 6379)
# - Neo4j (ports 7474, 7687)
# - InfluxDB (port 8086)
```

### 2. Verify All Services

```bash
# Check all containers are running
docker ps

# Should see:
# eip-postgres (PostgreSQL)
# eip-redis (Redis)
# eip-neo4j (Neo4j)
# eip-influxdb (InfluxDB)
```

### 3. Initialize Databases

```bash
# Generate Prisma client
npm run db:generate

# Push Prisma schema to PostgreSQL
npm run db:push

# Seed demo data (optional)
npm run seed:demo
```

### 4. Initialize Neo4j Schema

```bash
# Copy init script to container
docker cp infra/neo4j/init-schema.cypher eip-neo4j:/tmp/init-schema.cypher

# Execute schema initialization
docker exec eip-neo4j cypher-shell -u neo4j -p eip_neo4j_password -f /tmp/init-schema.cypher
```

### 5. Verify Access

**PostgreSQL:**
```bash
# Using Prisma Studio
npm run db:studio
# Opens: http://localhost:5555
```

**Neo4j:**
```bash
# Open Neo4j Browser
# URL: http://localhost:7474
# Username: neo4j
# Password: eip_neo4j_password
```

**InfluxDB:**
```bash
# Open InfluxDB UI
# URL: http://localhost:8086
# Username: eip_admin
# Password: eip_influx_password
```

**Redis:**
```bash
# Test connection
docker exec eip-redis redis-cli ping
# Expected: PONG
```

## Database Models (v2.0 Additions)

### Knowledge Graph Metadata (PostgreSQL)

**KnowledgeGraphEntity**
- Tracks entities in Neo4j with sync status
- Maps source system IDs to Neo4j node IDs
- Stores confidence scores and metadata

**KnowledgeGraphRelationship**
- Tracks relationships in Neo4j
- Stores confidence scores and evidence
- Marks inferred vs explicit relationships

### AI Model Registry (PostgreSQL)

**AiModelRegistry**
- Registry of available AI models
- Tracks capabilities, performance, cost
- Manages fallback chains

**ModelDecisionLog**
- Logs model routing decisions
- Tracks ensemble strategies
- Records confidence and latency

**ModelPerformanceLog**
- Time-series performance metrics
- Aggregated hourly
- Tracks success rate, latency, cost

### Self-Healing System (PostgreSQL)

**RemediationPlaybook**
- Defines remediation strategies
- Maps error patterns to actions
- Tracks success rates

**RemediationExecution**
- Logs each remediation attempt
- Records outcome and system snapshots
- Tracks escalations

### System Health (PostgreSQL)

**SystemHealthMetric**
- Metadata for InfluxDB metrics
- Defines metric types and categories
- Configures alert thresholds

### Federated Learning (PostgreSQL)

**FederatedLearningRound**
- Tracks training rounds
- Records participation and results
- Manages privacy budgets

**FederatedLearningParticipant**
- Tracks org participation
- Records contribution quality
- Handles update acceptance

## Data Flow Examples

### 1. Entity Extraction to Knowledge Graph

```
1. Connector syncs data from ERP
   ↓
2. Integration Hub extracts entities (Person, Product, Location)
   ↓
3. Knowledge Graph Engine creates entities in Neo4j
   ↓
4. Metadata saved to PostgreSQL (KnowledgeGraphEntity)
   ↓
5. Relationships discovered and created
   ↓
6. Relationship metadata saved (KnowledgeGraphRelationship)
```

### 2. AI Query with Model Orchestration

```
1. User asks natural language question
   ↓
2. Model Orchestrator analyzes query type
   ↓
3. Checks AiModelRegistry for best model
   ↓
4. Routes to selected model(s)
   ↓
5. Logs decision to ModelDecisionLog
   ↓
6. Combines results using ensemble
   ↓
7. Records performance to ModelPerformanceLog
   ↓
8. Writes metrics to InfluxDB (ai_model_performance)
   ↓
9. Caches result in Redis (cache:ai:query:*)
```

### 3. Self-Healing Incident Response

```
1. System detects error pattern
   ↓
2. Checks RemediationPlaybook for strategy
   ↓
3. Executes remediation actions
   ↓
4. Logs to RemediationExecution
   ↓
5. Writes metrics to InfluxDB (self_healing_event)
   ↓
6. Monitors for 5 minutes
   ↓
7. Updates success rate in RemediationPlaybook
```

### 4. Real-Time Dashboard Updates

```
1. Data changes in System of Record
   ↓
2. Connector syncs to PostgreSQL
   ↓
3. Event published to Redis pub/sub
   ↓
4. Dashboard service recalculates metrics
   ↓
5. Invalidates Redis cache
   ↓
6. Pushes update via WebSocket
   ↓
7. Writes performance metrics to InfluxDB
```

## Backup & Recovery

### PostgreSQL (Supabase)

Supabase handles backups automatically:
- Point-in-time recovery (PITR) available
- Daily automated backups
- Manual snapshots via Supabase dashboard

### Neo4j

```bash
# Backup
docker exec eip-neo4j neo4j-admin database dump neo4j --to-path=/tmp
docker cp eip-neo4j:/tmp/neo4j.dump ./backups/neo4j-$(date +%Y%m%d).dump

# Restore
docker compose -f infra/docker/docker-compose.yml stop neo4j
docker cp ./backups/neo4j-20240101.dump eip-neo4j:/tmp/neo4j.dump
docker exec eip-neo4j neo4j-admin database load neo4j --from-path=/tmp
docker compose -f infra/docker/docker-compose.yml start neo4j
```

### InfluxDB

```bash
# Backup
docker exec eip-influxdb influx backup /tmp/backup
docker cp eip-influxdb:/tmp/backup ./backups/influxdb-$(date +%Y%m%d)

# Restore
docker cp ./backups/influxdb-20240101 eip-influxdb:/tmp/restore
docker exec eip-influxdb influx restore /tmp/restore
```

### Redis

```bash
# Backup (RDB + AOF)
docker cp eip-redis:/data/dump.rdb ./backups/redis-$(date +%Y%m%d).rdb
docker cp eip-redis:/data/appendonly.aof ./backups/redis-$(date +%Y%m%d).aof

# Restore
docker compose -f infra/docker/docker-compose.yml stop redis
docker cp ./backups/redis-20240101.rdb eip-redis:/data/dump.rdb
docker cp ./backups/redis-20240101.aof eip-redis:/data/appendonly.aof
docker compose -f infra/docker/docker-compose.yml start redis
```

## Production Considerations

### Security

1. **Change default passwords** in production
2. **Enable SSL/TLS** for all connections
3. **Use secrets management** (AWS Secrets Manager, HashiCorp Vault)
4. **Restrict network access** with firewall rules
5. **Enable audit logging** for all databases
6. **Rotate credentials** regularly

### Scaling

1. **PostgreSQL**: Supabase handles scaling automatically
2. **Neo4j**: Consider Neo4j Enterprise for clustering
3. **InfluxDB**: Use InfluxDB Cloud or Enterprise for clustering
4. **Redis**: Deploy Redis Cluster for high availability

### Performance Tuning

1. **PostgreSQL**:
   - Add indexes for frequently queried fields
   - Use connection pooling (Supabase pooler)
   - Monitor slow queries

2. **Neo4j**:
   - Ensure proper indexes on entity IDs and org IDs
   - Increase heap size for large graphs
   - Use EXPLAIN to optimize queries

3. **InfluxDB**:
   - Configure appropriate retention policies
   - Implement downsampling for long-term data
   - Batch write operations

4. **Redis**:
   - Set appropriate maxmemory and eviction policy
   - Monitor memory usage and key count
   - Use connection pooling

## Troubleshooting

### Common Issues

**Cannot connect to database:**
1. Check container is running: `docker ps`
2. Check logs: `docker logs <container>`
3. Verify port is not in use: `netstat -an | grep <port>`
4. Check environment variables in `.env`

**Out of memory:**
1. Check container stats: `docker stats`
2. Increase memory limits in docker-compose.yml
3. Clear caches: Redis eviction, InfluxDB downsampling

**Slow queries:**
1. Check indexes exist
2. Use EXPLAIN to analyze query plans
3. Monitor slow query logs
4. Consider data partitioning
