## Vision

Transform EIP from a **great foundation** → **enterprise-grade platform** with:
- ✅ **System-agnostic connectors** (any REST/OpenAPI/DB system, not just Hospidia)
- ✅ **Custom KPI dashboards** (business can build own reports)

- ✅ **Flexible access control** (custom roles, attribute-based permissions)

## Track C: Autonomous Workflows

### Current State
- ✅ Rules (if healthScore < 50, send alert)
- ✅ Approvals (multi-step workflow)
- ✅ Reports (scheduled execution)
- ✅ All manual (Owner/IT must decide)

### v1.1 Deliverables
1. **Three Levels of Autonomy**
   - Level 1: Pure deterministic rules (no AI, safe to auto-execute)
   - Level 2: AI-assisted (Ellinea recommends, auto-approve if confidence > 95%)
   - Level 3: Scheduled workflows (pre-approved, runs unattended)

2. **Rule Enhancements**
   - autonomyLevel field (level1/level2/level3)
   - ellinea config (minConfidence: 0.95)
   - humanGate (require human review after execution?)

3. **Execution Engine**
   - Rule evaluator runs every 5 min
   - Checks all triggers (healthScore, alerts, events, schedule)
   - Executes actions (send alert, create approval, sync connector, run report)

4. **Cron Scheduler**
   - Scheduled workflows run via cron (2am daily, 7am weekday, etc.)
   - Pre-approved by Owner (no human gate needed)
   - E.g., "Daily Executive Brief at 7am"

5. **Audit Trail**
   - Every execution logged (trigger, decision, outcome, any errors)
   - Owner can review `/app/workflows/executions`

### Files
- `docs/21_v1.1_Autonomous_Workflows.md` — Design + implementation guide
- `services/identity/src/workflows/rule-evaluator.service.ts` — Rule engine
- `services/identity/src/workflows/cron-scheduler.service.ts` — Cron jobs
- `services/identity/prisma/schema.prisma` — Add `WorkflowExecution`, `ScheduledWorkflow` models
- `apps/web/functions/api/v1/orgs/me/rules/autonomous` — API endpoints

### Success Criteria
- ✅ Level 1 rules execute deterministically
- ✅ Level 2 rules consult Ellinea AI before auto-approving
- ✅ Level 3 scheduled workflows run on cron
- ✅ All executions audited
- ✅ Failures trigger alerts to Owner/IT

## Track D: Advanced RBAC (Custom Roles)

### Current State
- ✅ 6 fixed roles (owner, admin, executive, manager, member, viewer)
- ✅ Role-based access control (every user has one role)

### v1.1 Deliverables
1. **Custom Role Builder**
   - Owner can create roles like "Finance Manager", "Analyst", etc.
   - Pick permissions from a checklist (50+ fine-grained permissions)
   - Assign to users
   - `/app/settings/roles`

2. **Fine-Grained Permissions**
   - org:read, org:write, org:invite_user, org:suspend
   - connector:install, connector:sync, connector:delete
   - approval:decide, approval:escalate
   - report:create, report:run, report:delete
   - dashboard:create, dashboard:publish
   - data:read:people, data:write:documents
   - audit:read, admin:access

3. **Attribute-Based Access**
   - Permission → department/region/cost center match
   - E.g., "Finance Manager can read all finance dashboards (department='finance')"

4. **Conditions**
   - Time-based (9am–5pm only)
   - MFA required (for sensitive actions)
   - IP whitelist (access from office only)

5. **Temporary Elevation**
   - Owner can elevate user to admin for 60 min (emergency cover)
   - Auto-expires

6. **Delegation**
   - Owner can delegate specific permission to colleague for 7 days
   - E.g., "Can you approve these 3 expenses while I'm out?"

### Files
- `docs/22_v1.1_Advanced_RBAC_CustomRoles.md` — Design + implementation guide
- `services/identity/src/rbac/permission-evaluator.service.ts` — Permission engine
- `services/identity/prisma/schema.prisma` — Add `CustomRole`, `RoleAuditLog` models
- `apps/web/src/app/app/settings/roles/RoleBuilder.tsx` — UI
- `apps/web/functions/api/v1/orgs/me/roles/*` — API endpoints

### Success Criteria
- ✅ Owner can create custom roles

- ✅ Temporary elevation works (auto-expires)

## Track E: OAuth2 / SAML Enterprise SSO

### Current State
- ✅ Email/password auth via Supabase JWT
- ✅ Manual user invites

### v1.1 Deliverables
1. **OAuth2 / OIDC**
   - Support any OIDC provider (Google, Microsoft Azure AD, Okta, Auth0)
   - Generic OIDC handler
   - UI: "Sign in with Azure AD" button on login page

2. **SAML2**
   - Support SAML2 IdP (Active Directory, Okta, OneLogin, Azure AD)
   - Parse SAML assertions
   - Validate signatures

3. **Just-in-Time Provisioning**
   - First login via SSO → auto-create user
   - Extract email, name from SAML/OIDC claims
   - Assign default role

4. **Group → Role Mapping**
   - SAML groups (e.g., "AAD_Finance") → EIP roles (manager)
   - Config: "If user in group 'Finance', assign role 'manager'"

5. **Multi-org Support**
   - Same user can login to multiple linked orgs via single identity
   - SSO link at org level (each org has its own IdP)

6. **Enforcement**
   - Owner can enforce SSO (disable email/password login)

### Files
- `docs/23_v1.1_OAuth2_SAML_EnterpriseSSO.md` — Design + implementation guide
- `services/identity/src/sso/oauth2.service.ts` — OAuth2 handler
- `services/identity/src/sso/saml2.service.ts` — SAML2 handler
- `services/identity/prisma/schema.prisma` — Add `SsoProvider`, `SsoProviderUser` models
- `apps/web/functions/api/v1/auth/sso/*` — API endpoints
- `apps/web/src/app/login/page.tsx` — Login UI with SSO buttons

### Success Criteria
- ✅ Login with Azure AD works
- ✅ Login with Okta works
- ✅ Users auto-provisioned on first login
- ✅ Groups map to roles
- ✅ SSO enforcement works (no email/password)

## Risk & Mitigation

| Risk | Mitigation |
|------|------------|
| **OAuth2/SAML complexity** | Use well-tested libraries (openid-client, samlify); security review |
| **Permission checks on every endpoint** | Unit test permission evaluator; measure performance |
| **Cron job failures** | Audit log every execution; alert on failure; manual retry API |
| **Dashboard export slowness** | Async job queue + S3/R2 storage; don't block user |
| **Template maintenance burden** | Community contributions; template versioning |
